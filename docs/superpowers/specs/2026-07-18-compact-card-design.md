# Compact 卡片模式设计（状态栏 + 一句话结论 + 折叠详情）

日期：2026-07-18
状态：已确认

## 背景与目标

群聊里 agent 的回复目前全程流式渲染（思考面板、正文、工具面板实时刷新），
长回复会刷屏，淹没群里其他人的消息。群内的提问以业务排查为主，读者最需要
的是"排查出了什么结论"，而不是过程。

目标：新增一种 **compact 卡片模式**——

- 运行中：不流式输出中间内容，只显示一行实时状态（思考中 / 正在执行哪个工具）；
- 结束后：卡片顶部是一两句话的**排查结论**（无装饰 emoji），完整详情折叠，
  点击展开。

现有流式行为完整保留为 `streaming` 模式，不做迁移。

## 1. 配置

`preferences.cardStyle?: 'auto' | 'streaming' | 'compact'`，默认 `'auto'`：

| 值 | 行为 |
|---|---|
| `auto`（默认） | 普通群、话题群 → compact；p2p → streaming（现状） |
| `streaming` | 所有聊天保持现有流式卡片 |
| `compact` | 所有聊天使用 compact 卡片 |

- 话题群在 auto 下也走 compact：与群 UI 保持一致（已确认的设计主张）。
- resolver 与现有偏好项同款（`schema.ts` 中新增 `resolveCardStyle(cfg)`）。
- `/config` 卡片新增该选项，与两个群聊开关放同一分组。

## 2. 运行中形态（compact）

卡片仅包含：

```
🧠 正在思考…
或
🧰 Bash — npm test        ← 当前工具 header 行，实时更新
[⏹ 终止]
```

- `run-state.ts` 不变，照常积累完整 RunState（思考、正文、工具）。
- `renderCard` 增加 compact 分支：`terminal === 'running'` 时只输出状态行 +
  终止按钮。状态行复用 `toolHeaderText(tool)`（当前最后一个 running 工具），
  无工具时按 footer 状态显示 `🧠 正在思考…` / `✍️ 正在输出…`。
- 卡片更新只在状态/工具切换时发生，不随文本流刷新——顺带降低卡片更新
  频率，缓解限流。

## 3. 结束后形态（compact）

```
（总结未就绪时：⏳ 正在生成总结…）

库存扣减失败的原因是 order_item 表的 sync_status 未回写，
补偿任务 3 天前已停止调度                  ← 排查结论，无装饰 emoji
▸ 查看详情
   ├─ 完整回复正文（markdown）
   ├─ 🧠 思考过程（沿用现有折叠面板）
   └─ ☕ N 个工具调用（沿用现有折叠面板）
```

- done 事件到达 → 第一次更新：折叠详情 + `⏳ 正在生成总结…`；
  总结返回 → 第二次更新：填入结论。
- 详情面板受飞书 ~30KB 元素上限约束，沿用现有 `truncate` 策略。

## 4. 总结生成（独立轻量调用）

新增 `src/agent/summarize.ts`：

- `spawnProcess('claude', ['-p', '--model', 'haiku', ...])` 一次性调用，
  stdin 喂入最终回复正文（截断到安全长度）。
- prompt 要求：用一两句话给出排查/任务的核心结论，突出**原因和结果**，
  不要过程描述，不加 emoji。
- 15 秒超时；超时、非零退出、空输出一律兜底：截取回复首句（约 80 字符）。
- 不走 run 池 / session 机制，不占并发额度；失败仅记日志，不影响主流程。

## 5. 边界情况

- **异常结束**（interrupted / idle_timeout / error）：不调总结，显示现有
  状态行（`⏹ 已被中断` 等）+ 折叠详情。
- **短回复**（最终正文 < 100 字符）：跳过总结调用，正文直接平铺不折叠，
  避免"一句话回复还要点开"的反体验。
- **streaming 模式**：行为完全不变。

## 6. 测试

沿用 `thread-policy` 的纯函数测试风格：

- `renderCard` compact 分支快照测试：running（思考/工具两态）、done（含
  总结）、异常结束、短回复直出，共四类。
- `summarize` 单测：正常输出、超时兜底、非零退出兜底、空输出兜底。
- `resolveCardStyle` 各配置值 × 各 chatMode 的组合。

## 决策记录

- 总结来源选了"独立轻量 LLM 调用"（选项 3），弃用首句启发式（质量差）与
  prompt 约定（依赖 agent 遵守）；首句启发式仅作兜底。
- 配置粒度选了三态 `cardStyle`（选项 3），弃用"仅群聊硬编码"与"全局统一"。
- 群聊话题回复（`replyInThreadInGroup`）与本设计独立正交：compact 卡片
  解决"长回复刷屏"，话题回复解决"上下文隔离"，两者可叠加使用。
